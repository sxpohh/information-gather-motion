# 配音、字幕与混音

## 确定声音

先读用户已给的文案、音频和声音偏好。明确是无旁白、使用已有录音，还是需要TTS。用户已选音色时直接沿用；用户要求自然口语而尚未选音色时，按可用条件制作两三段同文案短样音，给用户试听选择，再生成全文。不把声音选择变成所有用户开工时的必填项。无可用TTS或声音不符合要求时，说明缺口，询问用户提供录音或选择可用方案；不要宣称已生成。

可以使用本机现成的Qwen3-TTS或其他可用TTS；先检查模型、运行环境、显存和授权，不要求所有用户安装某个模型或使用特定路径。采用外部在线服务前确认用户允许上传该文本/音频，且不得发送私有素材到未经授权的服务。声音的自然程度需要实际试听，尤其是专有名词、多音字、数字和语气衔接。不要声称TTS音色是真人，也不要未经许可克隆他人声音。

如果用户选择已有的Qwen3-TTS CustomVoice环境，Agent可读取该环境的实际使用方法；常见Python接口是 `Qwen3TTSModel.from_pretrained(model_dir, device_map=device, dtype=dtype)`，再调用 `generate_custom_voice(text=..., language="Chinese", speaker=..., instruct=...)`，把返回的音频按返回采样率保存。模型目录、Python、设备和speaker均取当前环境与用户选择，不硬编码。长稿分句串行生成，保留自然停顿；显存不足时说明情况并选择可行方案，不同时启动多个大模型。该接口是否可用以实际运行结果为准。

huashu-motion 0.3.1提供 `om voice --text` 和 `om voice --audio`，可作为独立工程中可选的配音与对齐工具。其源码提示默认Kokoro中文路径可能缺少声调；README仅明确macOS实测。Windows路径、缓存位置与当前环境是否可用需要自行验证。不要声称它已经与本模板一键集成；本模板使用下方的完整混音接口。避免将用户只允许写在特定磁盘的环境、模型和缓存写到其他位置。

## 工作顺序

1. 定稿后生成或取得旁白。逐段核听重点词与接缝；声音和文案有修正时，重新核对时间。
2. 先以无音频配置生成工作草案，读取 `timing.json` 中的 `duration`。根据旁白和阅读需求调整场景 `hold`、开场及结尾，再重新生成到新目录。
3. 以真实音频为依据制作 `captions`：通过可用的强制对齐/识别工具加人工检查，或由人工按听到的时间标注。自动对齐为估计，不要冒称逐字听审；无法确认时间就标明未完成。禁止用默认镜头字幕冒充配音字幕。
4. 用下面的工具生成与画面等长的完整WAV。旁白太长时工具会报错，应调整画面时长，不要截断、加速旁白或虚填音频时长。可指定一条有权使用的背景音乐；音效可预先包含在背景轨。仅有旁白时省略 `--music`。
5. 将WAV复制到素材目录，在配置中填写相对路径及实际时长，并写入核对过的 `captions`。重新生成到新的输出目录。存在 `audio` 时，模板关闭默认背景音乐及默认音效；**不要再把另一个背景音乐轨叠入这个完整混音**。
6. 浏览器按正常速度播放、人工试听关键读音和接缝，核对字幕位置、出现时间、音画同步及最终混音。检查成片完整解码、长度和实际音轨；没有人工试听时如实报告。

huashu-motion 0.3.1在使用模板的 `product-mix` 音轨时仍可能提示 `no soundtrack`。这条提示本身不能证明音轨缺失；检查最终MP4的音轨、播放及解码结果，也不要因为提示再叠加背景音乐。

## 混音命令

依赖本机 `ffmpeg` 和 `ffprobe`，输出路径必须不存在，输入和输出不得使用未授权的素材。`duration` 使用生成的实际 `timing.json`；`start` 是旁白在视频中的起点（秒）。

```sh
node "<SKILL_DIR>/scripts/mix-audio.mjs" --voice "<旁白音频>" --duration <影片秒数> --out "<素材目录>/mix.wav" --start 0 --music "<音乐音频>" --music-gain 0.12
```

工具将旁白与可选音乐混成48kHz立体声WAV，补足结尾静音并限制峰值；不会自动识别字幕、做动态压低或提供商业音乐授权。音量需试听后根据需要调整。路径、播放和模型依赖都需在当前环境确认，不能假定某台机器的安装位置。
